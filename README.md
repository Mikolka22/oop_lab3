# Что изменилось в третьей лабораторной

Сравнение с `lab2/oop_lab2`: линия теперь может взорваться на каждом шаге. Взрыв удаляет её голову и уменьшает заданную длину на единицу. Остаток продолжает движение по прежнему ромбу, а взрыв расширяется независимо от линии. Вероятность равна `p/1000`: 1 — 0,1%, 50 — 5%, 1000 — 100% на каждом шаге. Ниже приведены фрагменты текущих исходников, номера строк и связи между изменениями.

## 1. Новые параметры менеджера

**AppManager.h, строки 8–12:**

```cpp
    int chance, minRadius, maxRadius;
    bool colorful;

    int number(std::string text, int min, int max);
    int readNumber(const char* prompt, int min, int max);
```

`chance` хранит вероятность, `minRadius` и `maxRadius` — границы случайного конечного радиуса. В отличие от второй лабораторной, методы `number` и `readNumber` принимают допустимые границы `min` и `max`: одной проверкой теперь обслуживаются диапазоны 1–30, 1–1000 и 1–10.

**Связи:** значения считываются в `AppManager.cpp` и передаются в `Line::step`. В `Explosion` попадает уже выбранный радиус одного конкретного взрыва.

## 2. Проверка чисел с разными границами

**AppManager.cpp, строки 7–31:**

```cpp
int AppManager::number(std::string text, int min, int max) {
    int value = 0;
    if (text.empty()) return 0;
    for (unsigned int i = 0; i < text.size(); ++i) {
        if (text[i] < '0' || text[i] > '9') return 0;
        value = value * 10 + text[i] - '0';
        if (value > max) return 0;
    }
    if (value < min) return 0;
    return value;
}

int AppManager::readNumber(const char* prompt, int min, int max) {
    std::string text;
    int value;
    do {
        std::cout << prompt;
        if (!std::getline(std::cin, text)) return 0;
        value = number(text, min, max);
        if (value == 0) {
            std::cout << "Введите целое число от " << min << " до " << max << ".\n";
        }
    } while (value == 0);
    return value;
}
```

`number` отвергает пустую строку и любой символ, кроме цифры. После каждой добавленной цифры проверяет верхнюю границу, а в конце — нижнюю. Очень длинное число отвергается до переполнения: допустимый максимум здесь не превышает 1000. Ноль означает ошибку, потому что все разрешённые диапазоны начинаются с единицы.

`readNumber` вызывает эту же проверку в диалоге, показывает актуальные границы и повторяет запрос до правильного ответа. Если ввод закончился, возвращает ноль, чтобы менеджер завершился.

**Связи:** прежние три числовых параметра и новые три параметра используют одинаковую проверку. Ошибочные значения не доходят до классов `Line` и `Explosion`.

## 6. Отдельное хранение взрывов

**AppManager.cpp, строки 111–112:**

```cpp
    std::list<Line> lines;
    std::list<Explosion> explosions;
```

К прежнему списку линий добавлен список взрывов. Это два самостоятельных контейнера: удаление линии не удаляет созданные ею взрывы. Как и во второй работе, `std::list` сам управляет памятью, ручные `new` и `delete` не нужны.

**Связи:** `Line::step` добавляет сюда новые объекты, а менеджер обновляет и удаляет их отдельным циклом. Даже последний взрыв линии доходит до своего конечного радиуса.

## 7. Обновление двух видов объектов

**AppManager.cpp, строки 134–148:**

```cpp
        for (auto line = lines.begin(); line != lines.end();) {
            if (!line->step(console, now, chance, minRadius, maxRadius, explosions)) {
                line = lines.erase(line);
            } else {
                ++line;
            }
        }

        for (auto explosion = explosions.begin(); explosion != explosions.end();) {
            if (!explosion->step(console, now)) {
                explosion = explosions.erase(explosion);
            } else {
                ++explosion;
            }
        }
```

Линия получает вероятность, границы радиуса и ссылку `explosions` на общий список. Ссылка позволяет добавить взрыв прямо в существующий контейнер менеджера. `false` от линии означает, что она вышла за экран или её длина стала нулевой.

Следующий цикл независимо вызывает `Explosion::step` с тем же текущим временем. `false` от взрыва означает, что его последний этап закончился. При удалении `erase` возвращает следующий элемент, поэтому цикл не обращается к удалённому объекту и не пропускает соседний.

**Связи:** линия управляет своей скоростью, взрыв — своей. В менеджере нет общей задержки, которая задавала бы скорость обоим; прежний `wait(1)` только делает короткую паузу общего цикла. Потоки не добавлены.

## 8. Отрисовка через абстрактную фигуру

**AppManager.cpp, строки 150–158:**

```cpp
        console.clearFrame();

        for (Figure& figure : lines) {
            figure.show(console);
        }

```

В циклах используется `Figure&`: ссылка на общую базовую часть реальной линии или взрыва. Благодаря виртуальному `show` первый цикл вызывает `Line::show`, второй — `Explosion::show`. Объекты не копируются и не теряют свои данные.

Взрывы добавляются в кадр после линий и перекрывают их при совпадении координат. Между взрывами сверху оказывается более поздний объект в списке. Когда контур расширяется или исчезает, заново собранный кадр восстанавливает букву линии либо пробел.

**Связи:** общий интерфейс объявлен в `Figure.h`, реализации находятся в двух наследниках. Прежние `System::clearFrame`, `draw` и `present` работают без изменений и сохраняют правильное наложение.

## 9. Новый абстрактный класс Figure

**Figure.h, строки 1–9:**

```cpp
#pragma once

class System;

class Figure {
public:
    virtual ~Figure();
    virtual void show(System& console) = 0;
};
```

`class System;` заранее сообщает о существовании системного класса: для объявления ссылки полное определение пока не нужно. `virtual void show(...) = 0` — чисто виртуальный метод. Он требует реализации в наследнике и делает `Figure` абстрактным: отдельный объект `Figure` создать нельзя.

`virtual` означает, что вызов через `Figure&` выбирает реализацию фактического объекта. Виртуальный деструктор обеспечивает правильное уничтожение наследника, если в дальнейшем его будут удалять через указатель на базовый класс.

**Связи:** от этого класса публично наследуются `Line` и `Explosion`. Менеджер использует один способ вызвать их отрисовку.

## 11. Line наследует Figure и хранит оставшиеся буквы

**Line.h, строки 1–19:**

```cpp
#pragma once
#include "Figure.h"
#include "Explosion.h"
#include <list>

class Line : public Figure {
    int x, length, color, number, speed;
    unsigned long long start;
    std::list<int> symbols;

    int getX(int n);
    int getY(int n);

public:
    Line(int column, int size, int textColor, int lineSpeed, unsigned long long startTime);
    bool step(System& console, unsigned long long now, int chance,
              int minRadius, int maxRadius, std::list<Explosion>& explosions);
    void show(System& console) override;

```

`public Figure` задаёт публичное наследование: линия доступна через интерфейс фигуры. `override` просит компилятор проверить, что `show` действительно переопределяет виртуальный метод базового класса. Ошибка в имени или параметрах будет обнаружена при сборке.

Новый `std::list<int> symbols` хранит номера оставшихся букв в порядке от хвоста к голове. Во второй работе хватало непрерывного диапазона номеров. После взрывов появляются пропуски, поэтому перечисляются именно живые буквы: уничтоженная голова не появляется снова на следующем кадре.

`getX` и `getY` рассчитывают координаты по номеру. Новый `step` принимает параметры взрыва и список для его создания; поля скорости и времени рождения линии сохранены.

**Связи:** менеджер вызывает расширенный `step`, а виртуальный `show` использует `symbols`. `Explosion.h` подключён для параметра `std::list<Explosion>&`.

## 12. Общий расчёт координат головы и букв

**Line.cpp, строки 13–21:**

```cpp
int Line::getX(int n) {
    int dx[7] = {0, -1, 1, 0, -1, 1, 0};
    return x + dx[n % 7];
}

int Line::getY(int n) {
    int dy[7] = {0, 1, 1, 2, 3, 3, 4};
    return n / 7 * 5 + dy[n % 7];
}
```

Прежние массивы ромба вынесены в два метода. `n % 7` выбирает одну из семи позиций, а `n / 7 * 5` переносит следующий блок вниз на пять строк. `x` остаётся случайным столбцом конкретной линии.

**Связи:** те же методы используются в `Line::show` и при создании взрыва. Центр взрыва поэтому точно совпадает с координатой головы, а не с центральным столбцом всего ромба. Вариант №20 сохраняет движение сверху вниз.

## 13. Шаг линии со взрывом и уменьшением длины

**Line.cpp, строки 23–43:**

```cpp
bool Line::step(System& console, unsigned long long now, int chance,
                int minRadius, int maxRadius, std::list<Explosion>& explosions) {
    // Время каждого шага считаем от рождения линии, чтобы не копить задержку.
    while (now >= start + number * 1000ULL / speed) {
        unsigned long long time = start + number * 1000ULL / speed;
        symbols.push_back(number);
        if (static_cast<int>(symbols.size()) > length) symbols.pop_front();
        if (getY(symbols.front()) >= console.height) return false;

        // Вероятность chance/1000 проверяется один раз на каждый шаг линии.
        if (console.random(1, 1000) <= chance) {
            int radius = console.random(minRadius, maxRadius);
            explosions.emplace_back(getX(number), getY(number), radius, time);
            symbols.pop_back();
            --length;
        }
        ++number;
        if (length == 0) return false;
    }
    return true;
}
```

Каждый срок шага по-прежнему вычисляется от рождения линии. `1000ULL` означает число 1000 типа `unsigned long long`: умножение выполняется в широком целочисленном типе. Цикл обрабатывает и шаги, пропущенные из-за задержки. Для каждого сохраняется его плановое время `time`, которое становится временем рождения взрыва.

`push_back(number)` добавляет новую голову. Если букв больше текущей длины, `pop_front()` убирает хвост. `static_cast<int>` явно переводит размер контейнера в тип `int` для сравнения с `length`. Если даже хвост уже ниже окна, видимых букв не осталось и линия завершается.

Случайное целое от 1 до 1000 сравнивается с `chance`. При 50 подходят 50 исходов из 1000, при 1000 подходят все. Проверка выполняется один раз на шаг, а не на каждый проход быстрого цикла приложения.

Для успешного взрыва выбирается конечный радиус в пределах `minRadius..maxRadius`. `emplace_back` создаёт взрыв в общем списке: его центр — новая голова, начало — срок текущего шага. Затем `pop_back()` удаляет голову, а `--length` уменьшает дальнейшую длину линии на один символ. Номер следующей буквы всё равно увеличивается: путь не начинается заново и не останавливается. После нулевой длины возвращается `false`.

**Связи:** менеджер удаляет уничтоженную линию, но взрыв остаётся в своём контейнере. Буквы, оставшиеся в `symbols`, сохраняют прежние координаты. Пока линия только выползает, видимых букв может быть меньше заданной длины, как и раньше; взрыв уменьшает и этот предел.

## 14. Отрисовка сохранившихся букв

**Line.cpp, строки 45–52:**

```cpp
void Line::show(System& console) {
    // Храним номера оставшихся букв: взорванная голова больше не рисуется.
    for (int n : symbols) {
        char letter = 'A' + n % 26;
        Symbol symbol(getX(n), getY(n), letter, color);
        symbol.show(console);
    }
}
```

Вместо восстановления непрерывного диапазона метод перебирает только сохранённые номера. Буква определяется прежним выражением `'A' + n % 26`. Если уничтожена `C`, последовательность дальше доходит до `D`, а `C` не восстанавливается. Цвет оставшихся букв тоже не меняется после взрыва.

**Связи:** каждая буква по-прежнему рисуется объектом `Symbol`, который передаёт её в кадр `System`. Проверка границ находится в прежнем `System::draw`, поэтому выходящие за окно буквы не создают ошибок записи.

## 17. Собственная скорость и случайные цвета взрыва

**Explosion.cpp, строки 12–27:**

```cpp
bool Explosion::step(System& console, unsigned long long now) {
    if (now < start) return true;
    // Радиус увеличивается на одну клетку за 500 мс: 2 клетки в секунду.
    unsigned long long next = (now - start) / 500;
    if (next > static_cast<unsigned long long>(maxRadius)) return false;
    if (radius == static_cast<int>(next)) return true;
    radius = static_cast<int>(next);

    int count = 4 * radius;
    if (radius == 0) count = 1;
    for (int i = 0; i < count; ++i) {
        letters[i] = static_cast<char>(console.random(33, 126));
        colors[i] = console.random(1, 15);
    }
    return true;
}
```

Возраст взрыва делится на 500 мс. В момент рождения радиус равен 0 — одна клетка в центре; через 500 мс радиус равен 1, через 1000 мс — 2. Скорость составляет две клетки радиуса в секунду и не использует `speed` линии. Последний радиус тоже показывается 500 мс, после чего метод возвращает `false`.

Если этап не изменился, метод сразу возвращается: символы и цвета не перегенерируются на каждом кадре. При переходе на новый этап выбираются печатные символы с кодами 33–126 и цвета 1–15 отдельно для каждой позиции. `static_cast<char>` явно преобразует числовой код в символ.

Режим `colorful` сюда не передаётся, поэтому взрыв остаётся разноцветным и при `N`. В радиусе 0 обрабатывается один элемент; в остальных — `4 * radius`. Цвета случайные, поэтому отдельные значения могут совпадать с предыдущим этапом.

**Связи:** только менеджер решает, когда вызвать обновление, а сам взрыв определяет свой этап и срок завершения. `System::random` остаётся общим источником случайных чисел.

## 18. Расширяющийся контур ромба

**Explosion.cpp, строки 29–46:**

```cpp
void Explosion::show(System& console) {
    if (radius < 0) return;
    int i = 0;
    // Контур ромба: |dx| + |dy| = radius, как на первом рисунке задания.
    for (int dy = -radius; dy <= radius; ++dy) {
        int distance = dy;
        if (distance < 0) distance = -distance;
        int dx = radius - distance;
        Symbol left(x - dx, y + dy, letters[i], colors[i]);
        left.show(console);
        ++i;
        if (dx != 0) {
            Symbol right(x + dx, y + dy, letters[i], colors[i]);
            right.show(console);
            ++i;
        }
    }
}
```

Форма соответствует первому примеру задания: у радиуса 1 четыре клетки, у радиуса 2 восемь, у радиуса 3 двенадцать. Для каждой строки `dy` вычисляется её модуль `distance`, затем горизонтальное смещение `dx = radius - distance`. Это даёт контур `|dx| + |dy| = radius`.

Слева рисуется точка `x - dx`, справа — `x + dx`. При `dx == 0` точки совпадают, поэтому вторая не рисуется. Индекс `i` выбирает уже подготовленные символ и цвет каждой позиции. Старый контур не остаётся на экране: общий кадр каждый раз собирается заново.

**Связи:** используются прежние классы `Symbol` и `System`, которые не менялись. На границе окна невидимая часть контура обрезается `System::draw`, центр при этом не смещается. `main.cpp` также остался прежним: создаёт менеджер и вызывает `run`.
